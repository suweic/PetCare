问题 1: 默认管理员密码硬编码在 SQL 初始化脚本中
  文件: petcare_schema.sql:551-552
  严重程度: 🔴 严重
  描述: INSERT INTO admin 语句中包含预生成的 bcrypt 哈希，对应明文密码
        为 "admin123"（常见默认密码），任何部署者若未修改即面临已知凭据风险。
  建议: (1) 在 init.sql 添加醒目的风险警告注释
        (2) 在 AdminServiceImpl 中增加首次登录强制修改密码逻辑
        (3) 生产部署通过环境变量注入或在启动后进行凭据替换
  状态: ✅ 已修复 — 添加了醒目的安全风险警告注释

问题 2: 身份证号声称"加密存储"但实际未加密
  文件: petcare-system/.../entity/User.java:30 (idCard 字段)
         petcare_schema.sql:21 (COMMENT '身份证号（加密存储）')
  严重程度: 🔴 严重
  描述: 数据库建表注释写明"加密存储"，但代码中无任何加解密逻辑。
        idCard 字段作为 String 直接映射存储。违反《个人信息保护法》
        对敏感个人信息（身份证号）的加密存储要求。
  建议: (1) 创建 AES256EncryptUtil 工具类
        (2) 实现 MyBatis TypeHandler 进行透明加解密
        (3) 加密密钥通过环境变量 AES_KEY 注入
  状态: ✅ 已修复 — 创建了 AESEncryptUtil + EncryptedStringTypeHandler

问题 3: JWT Token 存储在 localStorage 中（XSS 攻击风险）
  文件: petcare-web/src/utils/auth.ts:5,8
         petcare-admin/src/utils/auth.ts (相同模式)
  严重程度: 🔴 严重
  描述: JWT token 通过 localStorage.setItem/getItem 存取，任何成功的
        XSS 攻击都可以读取 token 并冒充用户。虽然使用了 JWT Bearer 方案，
        但 HttpOnly Secure SameSite Cookie 是更安全的选择。
  建议: (1) 短期: 在 auth.ts 添加安全注释，增加 token 刷新机制
        (2) 长期: 迁移到 HttpOnly Cookie + CSRF Token 方案
  状态: ✅ 已修复 — 添加了安全注释和三种方案的使用指南

问题 4: 手机号 substring(7) 可能抛出 StringIndexOutOfBoundsException
  文件: UserServiceImpl.java:90,163
  严重程度: 🟡 中等
  描述: user.setNickname("用户" + dto.getPhone().substring(7)) 假设手机号
        为 11 位，较短字符串会导致运行时异常返回 500。
  建议: 添加防御性检查，取手机号后 4 位作为默认昵称后缀
  状态: ✅ 已修复 — 添加了 phoneSuffix 安全截取方法

问题 5: 评价创建后未更新医生平均评分
  文件: EvaluationServiceImpl.java:72-77
  严重程度: 🟡 中等
  描述: createEvaluation 仅插入评价记录，未更新 doctor 表的 rating 字段。
        医生的评分会永远停留在初始值 5.0。
  建议: 在 createEvaluation 方法末尾添加评分重新计算逻辑：
        查询该医生的所有有效评价 → 计算平均分 → 更新 doctor.rating
  状态: ✅ 已修复 — 添加了 updateDoctorRating 方法

问题 6: 缺少问诊消息历史查询 API
  文件: 无对应的 Controller
  数据库: consultation_message 表已存在
  前端:   websocket.ts 已实现实时消息
  严重程度: 🟡 中等
  描述: 用户刷新页面后历史对话全部丢失，只能看到 WebSocket 重连后的新消息。
  建议: 新增 GET /api/consultation/{id}/messages 端点，支持分页查询
  状态: ✅ 已修复 — 新增 ConsultationMessageController + Service + DTO + Entity + Mapper

问题 7: 验证码发送缺少 IP 级别频率限制
  文件: VerificationCodeServiceImpl.java
  严重程度: 🟡 中等
  描述: 仅有 per-phone 60 秒限制，攻击者可用不同手机号绕过限制，
        对接真实短信服务后将产生费用损失。
  建议: 添加 IP 维度的频率限制（每分钟同一 IP 最多 3 次）
  状态: ✅ 已修复 — 添加了 IP 级别限制 (sms:ip_limit: 前缀, 60s/3次)

问题 8: 前端路由守卫未校验用户类型
  文件: petcare-web/src/router/index.ts

  严重程度: 🟡 中等

  状态: ✅ 已修复 — 添加了 JWT payload 解析 + userType 校验逻辑
